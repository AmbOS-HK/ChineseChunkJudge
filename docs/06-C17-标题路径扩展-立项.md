# C-17 立项：标题路径扩展 `headingPath`

> 状态：**已实施**（0.8.0，2026-11-14）。字段、Schema、C# 透传与测试已同步；不新增判定规则。
> 关联：C-01/C-02 草案（`docs/05`）、`usagePurpose = rag_generation`。台账见 `docs/02` C-17。

## 1. 问题

切片只保留正文与偏移，不表达其在文档层级中的位置。对 `rag_generation` 用途，模型拿到的上下文无法判断「这段属于哪一篇哪一章」，导致：

- 拼 prompt 时无法按「篇—章—节」组织上下文；
- 生成文本的层级引用（「据第几章第几节」）无法自动生成或校验；
- 同一标题词（如「重点任务」）在多章重复出现时，块之间无法区分。

检索用途不受影响：向量匹配只看正文语义。

## 2. 字段设计

```json
{
  "chunkId": "structure@1200#37",
  "text": "第五节 重点任务……",
  "headingPath": ["第五篇 发展目标", "第二章 主要任务", "第五节 重点任务"]
}
```

| 项 | 规定 |
| --- | --- |
| 字段名 | `headingPath` |
| 类型 | `string[]`，从最外层到最内层，末项为块自身所属标题（若块正文以标题开头则含该标题） |
| 必填性 | **可选**；缺省表示执行器未产出，不视为缺陷 |
| 元素约束 | 不得为空串或纯空白；不得重复相邻同名项 |
| 长度 | 不设上限，建议 ≤ 6 层（超出属执行器问题，契约不强制） |
| 产出方 | 执行器 / 文档解析侧（与 `traits` 同源，见 C-02 边界） |
| 本仓职责 | 透传并保持顺序，不推断、不补全、不裁剪 |

## 3. 影响面

| 位置 | 变更 |
| --- | --- |
| `contract/schema/contract-chunk.json` | 新增可选 `headingPath`，`items: string`（不限制非空；本期不校验空串） |
| `contract/schema/raw-chunk.json` | 新增可选 `headingPath`，供执行器上报 |
| `contract/rules.md` | §6 字段表新增一行；新增 §6.1 `headingPath` 语义（实践落点，非 §13） |
| C# `RawChunk` / `ContractChunk` | 新增 `IReadOnlyList<string>? HeadingPath` |
| `ChunkJudgeService.Normalize` | 原样拷贝，不改内容 |
| `ChunkRelationBuilder` | 不参与，不生成标题链 |
| Judge 规则 | **本期不新增规则**；空串/重复项不校验（已按 §6 未决点默认处理） |

## 4. 版本判定

新增可选字段、不改既有语义 → 按 `rules.md` §12.1 走 **MINOR**：`0.7.1 → 0.8.0`。

## 5. 验收清单（实施时执行）

1. 两个 schema 通过 JSON 校验；`contract-chunk` 的 `required` 不含 `headingPath`。
2. C# 模型默认值为 `null`；`Normalize` 透传后顺序与内容完全一致。
3. 新增测试至少 3 项：透传保序、缺省为 null、空串元素不被本仓改写（是否报错取决于评审结论）。
4. `contract/openapi.yaml` 与 `contract/rules.md`、C# 常量三处版本同步为 0.8.0。
5. 文档：`docs/02` C-17 状态改为「已实施」，`docs/03` 增加 0.8.0 段。

## 6. 未决点（实施前需拍板）

本期取默认，均已按下列处理：

1. `headingPath` 空串/重复项：**不校验**（纯透传）。
2. 不要求「末项必须等于块自身标题」；不引入标题识别。
3. `ParentChildPackage` 的父块**不带** `headingPath`（本期 `ContextParentChunk` 不扩字段）。
