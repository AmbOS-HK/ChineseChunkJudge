# 07 C-18 选型入口接收模板集（立项）

- 状态：**已实施**（0.8.0，2026-11-14；与 C-17 同批）
- 实现：`TemplateResolver.Resolve(templates, categories, traits)`；单模板形态行为保持 0.7.1
- 验证：`dotnet build` 0 警告 0 错误；`dotnet test` 0.8.0 阶段 57 项通过（含新增模板集用例 5 项），对抗性自查后 64 项全部通过
- 立项日期：2026-11-14
- 目标版本：**0.8.0（MINOR）**，可与 C-17 同批，或单独排 0.8.x
- 前置：C-01/C-02 类别与特征产出方未冻结；本项**不依赖**类别枚举最终值，只依赖 `appliesTo.documentCategories` 的匹配语义

## 1. 背景

契约当前 `/templates/resolve` 的请求体要求传**单个** `template` 对象：

```yaml
TemplateResolveRequest:
  required: [template, documentCategories, traits]
```

后果：模板必须由调用方预先选定，`TemplateResolver` 只做「模板内部规则匹配 + 兜底」。这导致：

1. 每个宿主（AEC.Chat、Bench、第三方）都要自行实现「按类别选模板」，口径必然漂移；
2. 选错模板无法在统一位置复现，也无法进 Bench 对比；
3. `documentCategories` 虽为必填，但实现未使用，属误导性字段。

文档体系规划的功能是「按文档自动选型」。契约不应成为这项功能的限制条件。

## 2. 目标

让 `TemplateResolver` 成为**选型判定入口**：

```
特征（category / traits） + 模板集
   → ① 按 appliesTo 过滤候选模板
   → ② 候选内按 traits 匹配有序规则
   → ③ 无规则命中时按模板 fallback 兜底
   → TemplateDecision（可审计：选中哪个模板、命中哪条规则、是否兜底）
```

## 3. 非目标（边界不变）

- **不判特征**：`documentCategory` / `traits` 仍由调用方（特征产出方）提供，归 C-02；本仓不做解析、分类、NLP 推断。
- **不执行切分**：决策与执行分离不变，执行仍归外部执行器。
- **不判定策略优劣**：选型是否更优由 Bench 评测，不在本仓下结论。

## 4. 契约变更草案

### 4.1 请求

```yaml
TemplateResolveRequest:
  type: object
  additionalProperties: false
  required: [documentCategories, traits]
  properties:
    template:
      $ref: './schema/chunk-rule-template.json'
      deprecated: true
      description: "单模板（0.x 兼容保留，1.0.0 移除）。与 templates 互斥。"
    templates:
      type: array
      minItems: 1
      items:
        $ref: './schema/chunk-rule-template.json'
      description: "候选模板集，顺序即优先级。与 template 互斥。"
    documentCategories:
      type: array
      items: { type: string }
    traits:
      type: array
      items:
        $ref: './schema/chunk-rule-template.json#/$defs/trait'
```

约束：
- `template` 与 `templates` **恰好提供一个**；同时提供或都不提供 → 400。
- `templates` 为空数组 → 400。

### 4.2 响应

沿用现有 `TemplateDecision`，语义收紧：

- `templateId`：**实际选中的模板**（单模板模式下即入参模板）。
- `matchedRuleIndex`：选中模板内命中的规则下标；兜底时缺省。
- `usedFallback`：选中模板内是否走了兜底。
- 新增 `candidateCount`（integer）：参与类别过滤后的候选数量，用于审计。
- 新增 `selectionReason`（枚举：`rule_matched` / `fallback`）：本次结果来自规则命中还是兜底。

## 5. 选型算法（确定性，无模型参与）

1. **类别过滤**：保留 `appliesTo.documentCategories` 与请求 `documentCategories` 有交集的模板；无交集则剔除。
2. **优先级**：候选按请求数组顺序，顺序即优先级，部署方通过顺序表达偏好，不引入额外权重字段。
3. **规则匹配**：按顺序对每个候选执行现有规则匹配（`traits` 全包含才命中，先匹配先生效）。
4. **择优**：
   - 存在任一候选「规则命中」→ 取**顺序最前**的命中候选；
   - 全部候选均未命中 → 取**顺序最前**的候选执行其 `fallback`；
5. **无候选**：类别过滤后为空 → 400 `no_applicable_template`。

明确不采用「第一个候选无论是否命中都直接兜底」，否则通用模板会遮蔽专用模板。
