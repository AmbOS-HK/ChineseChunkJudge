## 2. 补丁 P1：结构父指针只补空值，不覆盖非空值

**契约依据**：`rules.md` §7.1 —— `parentChunkId` 是 deprecated 旧名、语义等同 `structuralParentChunkId`；「调用方已显式指定时保留原值，不覆盖」；「`parentChunkId` 保留以兼容现有消费方」。

**问题**：`Builders/ChunkRelationBuilder.cs` 当前把解析结果**同时写入两个字段**，导致两值恒等：调用方显式给出的另一个值被静默抹掉，CCJ-014（两值非空且不等才告警）永远不触发。

**目标行为**（按输入→输出，逐条都要满足）：

| 输入（`relations` 的两个指针） | 期望输出 |
| --- | --- |
| 都有且不同 | 各留原值，不抹平 → 判定阶段报 CCJ-014（warning） |
| 只有 `parentChunkId` | `parentChunkId` 保留，`structuralParentChunkId` 补成同值 |
| 只有 `structuralParentChunkId` | `structuralParentChunkId` 保留，`parentChunkId` 补成同值 |
| 两个都为空 | 按 heading 推断一次（沿用现有推断规则），两个字段写同一结果 |
| `previousChunkId`/`nextChunkId` | 保持现有行为：按 index 重算 |

**实现约束**：只补 `null`，绝不覆盖任何非空值；推断规则本身不得改变（普通块取最近前序 heading，heading 块取层级更浅的最近前序 heading）。

**必加测试**（新建测试文件，5 项，断言写死数值）：

1. 两值分别为 `parentA#0` / `parentB#0` → 构建后仍各自相等原值。
2. 只给 `parentA#0` → `StructuralParentChunkId == "parentA#0"`。
3. 只给 `parentB#0`（structural）→ `ParentChunkId == "parentB#0"`。
4. 两者都不给、前有 heading 块 → 两字段同为该 heading 的 `chunkId`。
5. 经 `ChunkJudgeService.JudgeContractChunks(...)` 喂冲突指针 → `Issues` 含 `CCJ-014` 且 `Severity=Warning`。**必须走服务入口**，不要直接调 `ChunkValidator`——绕过服务入口就是本补丁要修的路径。

## 3. 补丁 P2：CCJ-015 页码容错收窄

**契约依据**：§8.5「页码容错：句读 + 可选空白 + 1..4 位纯数字」。

**问题**：`RuleEngine/HardCutRule.cs` 的页码容错正则，在句读与数字之间多允许了一个闭合符（`】`/`》`/`）`/`”`/`’`），于是结尾形如 `。】123` 的恰长切片被豁免，而契约不允许。

**目标行为**：页码容错只接受「句读 + 可选空白 + 1..4 位数字」；闭合符只能出现在句读直接收尾的位置（属于正常句读判定），不能夹在句读与数字之间。

**实现约束**：不要整体改写 `IsHardCut` 的判定顺序与 `TrimEnd` 行为；只收窄页码容错的匹配范围。既有的"闭合符紧跟句读收尾判定为正常句读"必须保持。

**必加测试**（追加到既有 `RuleTemplateAndHardCutTests.cs`，2 项）：

1. `IsHardCut("甲乙丙丁戊。】123", 10)` → `true`。
2. `IsHardCut("甲乙丙丁戊。 123", 10)` → `false`；`IsHardCut("甲乙丙丁戊。123", 9)` → `false`。

**不得动**该文件既有用例 `ExactSizeWithPageNumberEnding_PassesByTolerance`（文本 `。 123`）：新行为下它仍应豁免。它变红说明收窄过头。

## 4. 补丁 P3：CCJ-003 的 detail.charCount 用真实码位数

**问题**：`RuleEngine/ChunkRuleEngine.cs` 的 `EmptyChunkRule` 把 `Detail["charCount"]` 固定写成 `"0"`，全空白切片一律报 0。

**目标行为**：`Detail["charCount"]` 必须等于该切片 `text` 的实际 Unicode 码位数（例如 3 个空格 → `"3"`；空串 → `"0"`）。用仓库已有的码位计数设施，不要另造一套（不得用 `string.Length`，那按 UTF-16 计，与契约的码位口径不一致）。

**必加测试**（追加到 `ChunkValidatorTests.cs`，1 项）：3 个空格的切片 → 该 issue 的 `Detail["charCount"] == "3"`。

## 5. 补丁 P4：traits 封闭枚举校验

**契约依据**：§13.1「`traits` 封闭枚举（`article_numbering` / `section_numbering` / `weak_structure` / `dense_table` / `pdf_no_structure`），扩枚举走次版本」。

**问题**：`Builders/TemplateResolver.cs` 的模板校验不校验 `traits`，未知取值被静默接受并走 fallback。

**目标行为**：`appliesTo.traits` 与 `decision.rules[].traits` 中任何不属于上述五个值的字符串，都必须在解析阶段被拒绝（抛 `ArgumentException`，消息里带上非法取值与其所在位置）。合法值不受影响。

**实现约束**：枚举来源要用 `Models` 里已有的 `ChunkTraits` 常量，不要在解析器里另抄一份字面量。**不要**顺手校验 `appliesTo.documentCategories`（不在本次范围）。

**必加测试**（追加到 `RuleTemplateAndHardCutTests.cs`，3 项）：

1. `decision.rules[0].traits` 含未知值 → 抛 `ArgumentException`。
2. `appliesTo.traits` 含未知值 → 抛 `ArgumentException`。
3. 五个合法 trait 各建一个模板 → 均解析成功、不抛错。

## 6. 补丁 P5：CCJ-008 补"子块 ID 重复"

**契约依据**：§8.3 CCJ-008 触发条件明确含「子块 ID 重复」。

**问题**：`RuleEngine/ParentChildRules.cs` 的 `ParentChildPairStructureRule` 已覆盖父块 ID 重复、`childChunkIds` 数组内重复，但没有检测子块 `chunkId` 的全局重复。

**目标行为**：双库开启时，若两个及以上子块 `chunkId` 相同，必须由 **CCJ-008** 报 error；同时 CCJ-016（chunkId 全局唯一）照旧报，两条并存是契约字面要求，不得为"去重"抑制其中任一条。

**实现约束**：只在 `parentChild.enabled` 生效时检查（该规则现有门禁不得改变）；issue 的 `chunkId` 指向重复的那个 id。

**必加测试**（追加到 `ParentChildRulesTests.cs`，1 项）：双库开启、两个子块 `ChunkId` 同为 `structure@600#0`、配对只列一次 → `Issues` 同时含 `CCJ-008` 与 `CCJ-016`。
