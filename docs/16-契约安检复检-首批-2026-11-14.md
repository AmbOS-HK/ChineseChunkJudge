## 2. K-26（安检能力）——已关闭

**改动**：新增 `scripts/check_contract_bump.py`。

判定链（任一不满足即 FAIL）：`contract/` 无改动 → 通过；有改动但版本未变 → 失败；版本位只允许三种（MAJOR 且低位归零 / MINOR 且 PATCH 归零 / PATCH +1）；§8.3 新增基础规则编号 → 至少 MINOR；删除基础规则编号 → 必须 MAJOR。

**证据 1（内置用例）**：`python scripts/check_contract_bump.py --self-test` → **9/9 通过**（覆盖无改动、改而不升、新增规则只升 PATCH、新增规则升 MINOR、删规则只升 MINOR、删规则升 MAJOR、跳两段、回退、只改 Schema 升 PATCH）。

自测过程中发现并修正一处自身逻辑错误：`0.9.0 → 1.0.0` 被误判为"跨两段"，实为合法的 MAJOR（minor/patch 归零）。修正为按"版本位类型"判定后 9/9 通过。

**证据 2（临时 git 仓库端到端，不动本仓库）**：

| 场景 | 结果 |
| --- | --- |
| 加了 `CCJ-018` 但版本仍 0.9.0 | FAIL：契约有 1 个文件改动，但版本仍为 0.9.0 |
| 同改动并升到 0.10.0 | PASS：契约改动与版本位匹配（0.9.0 → 0.10.0） |

**接入**：`.github/workflows/ci.yml` 新增 `contract-bump` 作业，仅 PR 触发，基线取 `origin/<base_ref>`。
