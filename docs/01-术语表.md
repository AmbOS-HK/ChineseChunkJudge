# 01 术语表

## A. 现行术语（契约已定义，禁止另造同义词）

| 术语 | 字段 / 英文 | 定义 | 出处 |
| --- | --- | --- | --- |
| 文档特征 DocumentFeature | `documentId`、`metadata`、`content`、`language`、`structureHints` | 一次判定请求的输入：正文 + 元信息 + 可选结构提示 | rules.md §4、`schema/document-feature.json` |
| Metadata 五字段 | `title`、`sourcePath`、`documentType`、`pageInfo`、`createTime` | 固定五字段，不可删减、改名、改类型 | §4.1 |
| 原始切片 RawChunk | `index`、`text`、`startOffset`、`endOffset` 等 | 执行器产出、未补契约字段的片段 | §6 |
| 契约切片 ContractChunk | 见 §7 表 | 已补元信息、字符数、关系指针，是判定对象 | §7 |
| 关系 relations | `previousChunkId`、`nextChunkId`、`structuralParentChunkId`、`contextParentChunkId` | `parentChunkId` 为 deprecated 旧别名（1.0.0 移除），语义等同结构父；同现不一致触发 CCJ-014 | §7.1 |
| 策略名 strategy | `{type}@{targetSize}` | 如 `structure@600`、`sentence@900` | §5.1 |
| 基础规则 base rule | `CCJ-001..016` | 强制生效，任何实现不得删除、不得降级 | §8.3、§8.4 |
| 扩展规则 | `CCJ-X###` | 只能新增问题，不得豁免基础规则 | §10 |
| 字符数 charCount | `charCount` | Unicode 码位数 | §11 |
| 判定报告 JudgeReport | `reportId`、`documentId`、`strategy`、`passed` 等 9 项 | 一次判定的完整结果 | §9 |
| 单元类型 unitKind | `heading` / `article` / `paragraph` / `sentence` / `table` / `code` | 结构单元类别 | §4.2 |
| 双库（Parent/Child 双分片库） | `parentChild.enabled`、`ParentChildPackage` | 同一份文档拆成两类 Chunk：**子块**（Child，细粒度，进检索索引，负责向量召回）+ **父块**（Parent，粗粒度上下文块，单独存放，召回子块后取回供 LLM 上下文）。用小块去搜，大块用来回答。**不是**两个独立向量库软件，可同库不同 collection / 分区；框架**不负责向量库读写**，只产出配对结构；默认关闭，下游可选 | §5.3、§7.3 |
| 结构父 structuralParentChunkId | `structuralParentChunkId` | 文档大纲层级的最近前序 heading 父节点 | §7.1 |
| 上下文父 contextParentChunkId | `contextParentChunkId`、`ContextParentChunk` | 双库模式下与子块配对的聚合父块；取自原文、互不重叠、全文划分（CCJ-010） | §7.1、§7.2 |
| 父子配对 ContextParentChildPair | `contextParentChunkId` + `childChunkIds[]` | 1:N 为主，1:1 合法，数组非空；父侧为权威，子侧为派生视图 | §7.3 |
| 父子产物包 ParentChildPackage | `documentId`、`strategy`、`generatedAt`、`parentChunks`、`pairs` | 独立输出产物，与 `JudgeReport` 解耦 | §7.3 |
| 切片规则模板 ChunkRuleTemplate | `templateId`、`version`、`appliesTo`、`decision`、`validation` | Spec 侧选型判定：文档特征 → 切分方式 + 参数 + 验证口径；有序规则 + 强制 smart 兜底；只决策不执行 | §13 |
| chunkMode | `regex` / `smart` / `page` | 切分方式枚举；`regex` 带 `pattern` 与禁忌枚举字段；`page` 豁免 CCJ-015 | §13.2、§5.2 |
| 恰长硬切 | CCJ-015（error）、`hardCutChunkCount` | 切片长度恰等于 chunkSize 且结尾不在允许句读集合（页码容错）；每文档计数须为 0 | §8.5 |

**易混淆点**：`metadata.documentType` 是**载体**枚举（`text` / `markdown` / `html` / `pdf` / `docx` / `other`），**不是**业务文档类别（政府报告、司法鉴定等）。业务类别在现行契约中没有字段承载。

## B. 规划态术语（契约未定义，仅限规划文档内部使用）

| 术语 | 规划含义 | 契约现状 | 落地条目 |
| --- | --- | --- | --- |
| 分流 chunk routing | 按文档特征把文档路由到某个切分策略与参数组 | **已由 C-10 落地**（0.3.0）：`decision` 有序规则 + 强制兜底，见 A 组「切片规则模板」 | C-04（并入 C-10） |
| 分流规则引擎 | N 分流、配置驱动的路由组件 | **不另立**：模板 + 调用方查表，无独立运行时组件 | C-04/C-05（并入 C-10） |
| 特征提取器 | 识别业务文档类别、是否带表格、是否 OCR、结构化层级 | `DocumentFeature` 无对应字段；`structureHints` 只有 `headingCount` 与 `unitBoundaries`；模板 `traits` 目前由调用方提供 | C-01、C-02 |
| payload 模板 | 按模板渲染的下游载荷 | `ContractChunk` 无 `payload` 字段 | C-03 |
| 质检判定（Judge 侧） | 判定切片结果是否合规 | **已落地**：CCJ-001..016、`JudgeReport` | 0.2.0 – 0.7.0 |
| 判定单 | —— | **误用**：契约术语为「判定报告 JudgeReport」 | 禁用，见 C 表 |

## C. 禁用词表（对外文案、提交信息、代码注释中不得使用）

| 禁用 | 应改为 | 理由 |
| --- | --- | --- |
| 判定单 | 判定报告 / `JudgeReport` | 契约无此术语，§9 已定名 |
| 双库（指两个独立向量库软件，或宣称 6000 为标准阈值） | Parent/Child 父子配对产物 `ParentChildPackage`；6000 为临时调试值 | 0.2.0 已落地（见 A 组），禁用的是错误指向与无依据的阈值宣称 |
| `parentChunkId`（不指明是哪一种父） | `structuralParentChunkId` 或 `contextParentChunkId` | 两个“父”语义不同，混用会让调试与评测分不清 |
| 五分流（当作策略类型讲） | 策略名 `{type}@{targetSize}`；分流是路由维度，不是 `type` | §5.1 只约束 `type` 形态 |
| chunk 算法库 | 切片判定框架 / 契约 | 项目定位不是算法库 |
| 1500 例外（若无契约变更） | CCJ-004 告警（不阻断） | §8.2 告警阈值、§8.4 不得豁免 |
