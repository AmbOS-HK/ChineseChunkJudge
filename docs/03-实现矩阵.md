## 3. 已知缺口（如实记录）

1. **CCJ-006 无独立单元测试**：规则已实现，但 12 个测试方法里没有针对相邻重叠的用例。补测待办。
2. `ContractConstants.ContractVersion` 在 C-00 之前无任何引用（仅定义处），因此版本号写错不会被测试发现；C-00 已把值对齐到 0.1.1。
3. Go / Python / Rust 无任何可执行验证；跨语言一致性目前只靠 `contract/openapi.yaml` 与 JSON Schema 人工比对，仓库内**未引入** Schema 校验工具或契约测试套件。
4. `samples/DemoConsoleApp` 依赖仓库外插件桩才能运行，仓库内无自包含的端到端验证路径。

## 4. 新实现准入基线（建议，尚未写入契约）

任何新增语言的参考实现，建议至少满足：

1. 通过 `contract/schema/*.json` 六个 Schema 校验（2020-12）。
2. 实现 CCJ-001..014 全部判定，`JudgeReport` 字段与 §9 一致（含双库 summary 字段）。
3. 覆盖 `/judge`、`/chunks/normalize` 与 `/packages/parent-child` 的契约测试。
4. 在实现文档中显式声明 `startOffset` / `endOffset` 的字符下标口径（§11），并说明与 UTF-16 code unit 的换算关系。
5. 不内置切片算法与文档解析器（§1.1、§3.1）。

上表第 1、3 条要成为硬门槛，需先在 `contract/` 中定义，属 C-04 之后的独立变更，未列入台账。
