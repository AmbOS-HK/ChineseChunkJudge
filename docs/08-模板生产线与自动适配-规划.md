# 08 模板生产线与自动适配（规划）

- 状态：**规划，未实施**
- 日期：2026-11-14
- 关联：C-02（特征产出方）、C-09（模板托管范围外）、C-18（模板集选型，0.8.0 已实施）
- **不改 `contract/`、不新增契约条目**：本文描述模板如何产生、验证、晋升，不改变「合法模板长什么样」

## 1. 要解决的问题

0.8.0 已支持 `/templates/resolve` 接收模板集，但模板从哪来仍未闭环：

- 现有模板命中不了新类别/新结构时，调用方只能退回 smart；
- 每次退回都丢掉一次可沉淀的证据；
- 没有机制让「经过大量真实文档验证的模板」逐步替代兜底。

本文定义一条可累积的模板生产线，让模板随真实送切物增长而进化。

## 2. 三层结构

```
运行时：
  ① 检索现有模板（0.8.0 templates[]）→ 命中即用
  ② 未命中 → 在线候选模式（单批生效）→ 当场校验 → 用或退回
  ③ 候选不成立 → smart + 契约尺寸兜底

离线：
  ④ 证据累计 → 多文档复评 → Bench → 人审 → 晋升共享模板（供下一次①使用）
```

三层职责不同，不得混用：

| 层 | 产物 | 生效范围 | 谁负责 |
| --- | --- | --- | --- |
| ① 检索 | 已有模板的决策 | 全局 | 本仓 `TemplateResolver` |
| ② 在线候选 | 临时模板 + 证据 | **仅本批** | 部署侧工具链 |
| ③ 兜底 | `chunkMode=smart` 决策 | 全局 | 契约强制 |
| ④ 晋升 | 共享模板（带版本） | 全局 | 离线评测 + 人审 |

## 3. 自动适配的两种实现

「按送切物特点适配」成立，但实现不同，可复现性不同：

### 3.1 确定性派生（可进运行时）

特征 + 版本化派生规则 → 模板。要求：

1. 特征由请求固化，不运行时现判；
2. 派生规则是版本化资产（如 `derived-rules@r1`）；
3. 模板 ID 由「特征签名 + 规则版本」确定，不随机；
4. 同一输入必得同一模板、同一判定报告。

### 3.2 模型生成（在线仅限候选模式）

模型读特征后按本仓规范写规则。规范约束保证**合法**，不保证**有效**：

- 封闭枚举、`chunkSize` 1..1500、`fallback=smart`、regex 必带 `pattern`；
- 正则安全：禁 `^` 多行锚、禁标题切分、限制回溯与执行超时；
- 单文档 Judge 通过只证明「对本文件合法」，不证明泛化。

因此模型生成在线只能产出「候选」，不得直接晋升。

## 4. 在线候选模式

### 4.1 流程

```
送切物 + 特征
  → 生成候选模板（按规范）
  → 静态校验（Schema + 正则安全 + 尺寸 + fallback）
  → 用该文档执行切片
  → Judge（CCJ-001..017）
  → 与 smart 基线对比（硬切数、边界完整性、尺寸合规、覆盖率）
  → 通过：本批使用；不通过：退回 ③
```

### 4.2 必做约束

1. **产物固化**：候选必须落成完整 JSON，带 `templateHash`、`origin=generated`、生成依据（特征签名、规则版本、所用样本），不得只留在内存。
2. **按签名缓存**：同一 `featureSignature` 复用同一候选模板，禁止逐文档各生成一套。
3. **单批生效**：标 `singleBatch` 或 `expires`，默认不进入共享模板库。
4. **必须有兜底**：模型超时、返回非法 JSON、静态校验失败，一律走 ③，不得阻断导入。
5. **不得自动加载**：候选文件不得被 `TemplateResolver` 或宿主默认读取，必须由本批显式传入。

### 4.3 特征签名

建议字段：

| 字段 | 说明 |
| --- | --- |
| `documentCategory` | 业务类别 |
| `traits` | 封闭枚举集合，排序后拼接 |
| `headingDepth` | 标题最大深度 |
| `tableRatio` | 表格字符占比分档 |
| `avgParagraphChars` | 平均段长分档 |
| `sourceGroup` | 来源/单位/年度分组（用于防同源过拟合） |

签名用于缓存与证据归档，不进入契约。

## 5. 证据模型

每一批在线候选至少沉淀四项：

| 证据 | 内容 | 用途 |
| --- | --- | --- |
| 特征签名 | §4.3 | 判断适用面 |
| 模板产物 | JSON + `templateHash` + 来源 | 复现与审计 |
| 判定结果 | `JudgeReport` | 结构合规 |
| 对照基线 | 同批文档的 smart 兜底结果 | 证明「不比兜底差」 |

缺少任一项，该批不进入晋升评估。

## 6. 晋升与回退

### 6.1 晋升门槛（建议值，待拍板）

| 条件 | 建议 |
| --- | --- |
| 同签名样本量 | ≥ 30 份（可按类别调整） |
| 来源覆盖 | ≥ 2 个来源/年度/结构变体 |
| 硬切数 | 0 |
| 边界完整性、尺寸合规 | 不低于 smart 基线 |
| Bench 指标 | 不低于基线与现役模板 |
| 旧样本回归 | 不退化 |
| 人审 | 必须 |

任一不满足，候选保持 `singleBatch`，不晋升。

### 6.2 回退

- 晋升后新样本出现硬切、边界破损或 Bench 退化，先回退到上一版本，不直接删除；
- 回退记录写入模板版本历史，保留原因与证据引用。

### 6.3 版本

- 模板 `version` 独立于契约版本，按模板自身变更递增；
- 晋升即产生新版本，旧版本保留可回退；
- 同一 `templateId` 不得原地改写语义而不升版本。

## 7. 与现有模块的边界

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `contract/` | 合法模板的结构与字段 | 模板怎么产生、怎么晋升 |
| `TemplateResolver` | 在给定模板集内选型 | 生成模板、评测质量 |
| Judge | 结构合规判定 | 判断「切得好不好」 |
| Bench | 多文档质量评测 | 产出模板 |
| 部署侧工具链 | 在线候选、证据归档、晋升流程 | 改契约、改判定规则 |
| 特征产出方（C-02） | 产出类别与 traits | 决定模板参数 |

## 8. 明确不做

1. 不把生成器接进 `/templates/resolve`；
2. 不让候选模板自动进入共享库；
3. 不以单文档 Judge 通过作为晋升依据；
4. 不把「模板越多」当成「模板越好」；
5. 不在契约中新增 `templateOrigin` / `featureSignature` 字段（如未来需要，另行立项）。

## 9. 未决点

1. 晋升样本量按类别统一还是分类别设定；
2. `featureSignature` 的分档口径由谁维护（部署侧还是 Bench）；
3. 候选模板是否允许跨批次复用（同签名但不同批次）；
4. 「旧样本回归」的最小回归集规模与更新频率；
5. 在线候选的时延与成本上限，超限时是否直接降级为 ③。

## 10. 一句话

**在线产生证据，离线做裁决，晋升后反哺检索。** 模板的进化不是靠生成得多，而是靠同一签名下、有基线、可回归、过 Bench 的证据积累。
